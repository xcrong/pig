# pig v1.1.0 (2026-09-30)

The first feature release after pig settled into a general-purpose Agent Harness: all first-party telemetry and the image/video generation tools are gone, the hard binding to a Grok account is lifted, and a fresh install goes straight into the provider setup wizard. It also picks up the upstream command sandbox isolation and egress-proxy subsystems.

## New features

- First-run guidance: when no credential is present, the welcome page offers a Setup provider entry (`s` or Enter), lists the built-in vendors and checks whether the matching `env_key` is set, then writes the confirmed or pasted value into the trusted `config.toml`. A custom provider can also be entered step by step (id, base URL, model, backend, credential) and lands in `model_providers` and `model`. The entry point is no longer a dead end.
- The custom provider wizard gained backend selection guidance: `base_url` reuses the vendor normalization rules (a messages gateway automatically gets `/v1` appended) and branches between a messages gateway and a direct Anthropic connection — the direct path writes `anthropic-version` (default `2023-06-01`) and `auth_scheme = x_api_key`. The confirmation page shows the authentication method that actually takes effect, whether the env was found, and hints for advanced fields such as responses.
- Vendor snapshots update automatically: the build step fetches the latest model slice from pi.dev and compiles it into the binary (falling back to the in-repo git snapshot when offline or sandboxed), while a background task refreshes the cache under `~/.config/pig/vendors` at runtime. Load priority is "explicit file > automatic cache > built-in", and a vendor that is not enabled never triggers a fetch.
- Command sandbox isolation: the upstream sandbox command subsystem and egress proxy are ported in, and workspace takes over sandbox and gate decisions. Sandbox mode supports `off` / `observe` / `enforce`, layered as "remote rollout switch < user `config.toml` < workspace layer (may only tighten, never loosen) < `GROK_SANDBOX_MODE`"; when the current layer is refused it is handled as enforce and its source is marked.
- MCP servers support `bearer_token_file`: the Bearer token is read from a file and **re-read on every request**, so a credential rotated on disk applies without reconnecting; it takes precedence over a configured `Authorization` header. The path supports setup template substitution.
- New npm package `@xcrong/pig`; postinstall downloads the prebuilt binary for the platform from the GitHub Release and records `installer = npm` so later updates are handled by the package manager.
- Permission path matching upgraded to dual matching, sandbox-related gates closed up, clipboard operations serialized, MCP servers deduplicated.
- Leader mode suggestions arriving via `/v1/settings` now keep the process alive instead of being a one-time notice, recap moved to a token-saving formulation, per-path concurrency, and the suggest routing was reordered.

## Fixes

- Fixed the Setup provider wizard being keyboard-only: all three lists now support the mouse — hover highlights and selects, click selects or confirms, clicks inside or outside the box are swallowed and never fall through to the welcome menu underneath, and stale hit-rects are cleared on small terminals to prevent panics.
- Fixed the welcome page showing a red error with no credential present and repeatedly steering the user back into the same error.
- Fixed the `xai-grok-config` test target failing to compile: the remote-settings case in `sandbox_mode_tests.rs` was ported from upstream with a `crate::remote_settings` import, but that struct actually lives in `xai-grok-config-types` (which depends on this crate, so the reverse import is impossible). The case has been moved to `xai-grok-config-types`, and `cargo test -p xai-grok-config` runs again.
- Fixed when the bearer token file is read (previously read once at connect time, so a rotation did not take effect).
- Cleared a batch of standing `cargo build` warnings: write-only intermediate values, unreachable `pub` narrowed to `pub(crate)`, and meaningless `drop` calls.

## Branding and interface

- The product name in the interface is unified as Pig Agent; the welcome page version badge, subtitle and trust notice no longer carry upstream `Grok Build` wording.
- The `pig --version` banner now uses a `pig` prefix.

## Breaking changes

- **Grok OAuth browser login and startup-forced authentication are removed.** The xAI OIDC loopback callback, the device code flow, and the automatic browser launch on startup are all gone; the `pig login` / `grok login` command entries, `--oauth` / `--device-auth`, and environment variables such as `GROK_LOGIN_DEVICE_FLOW` no longer exist. Credentials are now configured through `[vendors.<id>]` (`enabled` + `env_key`) or `[model_providers.*]`; the TUI starts directly and no longer opens a browser when no credential is present. Users who relied on signing in with a Grok account need to move to provider configuration.
- **All first-party telemetry is removed.** The `xai-grok-telemetry`, `xai-grok-otel` and `xai-mixpanel` crates and all their call sites are gone, and the `[telemetry]` config section and related `GROK_TELEMETRY_*` environment variables are no longer read. Ordinary logging and local crash report files are kept.
- **Image/video generation tools removed**: `/imagine`, `/imagine-video` and the image_gen / image_edit / image_to_video / reference_to_video tools are removed, narrowing pig to a general-purpose Agent Harness.
- **The updater now goes through GitHub Release and package managers**: `installer` is narrowed to `npm` / `github` / `winget` / unknown, and the XAI download path, the enterprise update channel and `install.sh` are deleted. A direct binary discovers its version over plain HTTPS from the `xcrong/pig` Release and downloads and unpacks the tarball.
- Release artifacts are narrowed to linux x64 and macOS arm64 (ubuntu-arm / mac-intel / windows are not published for now).

## Build and release

- New `publish-npm` job: after the tag is pushed it aligns the `npm/pig` version automatically and publishes through OIDC trusted publishing (no long-lived token). Prerelease tags (with an `-N` suffix) automatically go to the alpha channel.
- `[cli].auto_update` remains off by default, so pig will not be overwritten by upstream artifacts; the update source itself still points upstream.
- The dev profile disables debuginfo to speed up local iteration.

## Other

- Upstream baseline: monorepo `036a5d8` (version 1.0.41); no upstream sync in this release. Sandbox isolation and core changes were ported selectively by P0/P1 priority.
- Recorded the current "no first-party telemetry egress" state in the `AGENTS.md` merge-protection list, so a later upstream sync does not quietly bring first-party sinks back.
- Documentation adds a TUI mouse convention (every list and button reachable by keyboard must also support the mouse).
