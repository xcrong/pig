# pig v1.0.1（2026-09-28）

首个独立版本号版本：pig 不再跟随上游版本编号，在当前基线之上自行递增。内容上 vendor 模型能力补齐（推理档位、可区分命名）、vendors 显式启用，以及一个上下文窗口配置修复。

## 新功能

- Vendor 模型支持推理档位：从快照数据按 pi 规则派生 effort 菜单，`/effort` 与 `/model <model> <level>` 可直接用于 vendor 模型，无需手写配置；上游新增档位会自动跟随。
- Vendors 改为显式 opt-in：只有 `[vendors.<id>] enabled = true` 才会加载该 vendor 的模型目录；凭证只读取配置里的 `env_key` / `api_key`，无凭证启用会告警（BYOK 裸跑是有意识的选择）。`--config` 补丁与 campaign 远端补丁不能开启这类来源。
  - ⚠️ 行为变更：之前默认加载 vendor 模型的，需要在 `config.toml` 里显式启用，例如：
    ```toml
    [vendors.opencode-go]
    enabled = true
    env_key = "OPENCODE_API_KEY"
    ```

## 修复

- 修复显式配置的 `context_window` 恰好等于默认值（256000）时，被 vendor 同名条目覆盖的问题；现在只要在 `[model.*]` 里写了就一定生效。

## 品牌与界面

- Vendor 模型名默认带目录 key 后缀（`名字 (vendor/id)`），`/model` picker、设置面板、状态栏处处可区分；所见即所提交。
- 状态行、空状态 composer、欢迎页只显示模型短名，界面更干净；完整名仍保留在 picker、设置等需要区分的地方。

## 构建与发布

- 版本号独立：pig 不再跟随上游版本编号，`v*` tag 即发版（`Cargo.toml` 版本、tag 后缀、日志文件名保持一致）；将来需要对齐上游时再整体 bump。旧 `pig-v*` 命名废弃，历史 tag 与日志保留不动。

## 其他

- Vendor 快照同步至上游 2026-09-28 目录：opencode 76 个、opencode-go 29 个；新增 `longcat-2.5-preview-free`；opencode-go 下线 `kimi-k2.6`、`glm-5.1` 等 4 个模型（opencode 侧仍可用）。
- 上游基线：monorepo `036a5d8`（版本 1.0.41），本次无上游同步。
