# pig v1.1.1 (2026-10-01)

Highlight: the Windows release target is back, with a full batch of Windows build-compatibility fixes.

## Fixes

- Cleared all 9 warnings reported by `cargo check` on Windows: gated the `clipboard` cross-platform imports on Linux, restructured the arboard error pass-through to drop the dead initial assignment, and gated unused parameters, imports, and functions per platform in `terminal`, `probe`, `workspace_server`, and `shell-terminal`.
- `protoc` invocations now use scratch files instead of assuming `/dev/null` and `/dev/stdout`, so codegen works on Windows too.
- Added main-thread stack reserve for Windows targets (MSVC `/STACK:16MiB`, gnu `--stack`) to relieve stack overflows in deeply recursive paths.
- Gated platform-specific tests and examples with `cfg`: symlink-planting cases, argv-shape assertions, and the sandbox smoke test are skipped on Windows, so the suite passes without privileges or developer mode.
- `HeldDir::replace` now writes with rename semantics: a link at the target is replaced by the rename instead of written through.

## Build & Release

- Added `windows-2025` back to the release matrix, producing `pig-windows-x86_64.tar.gz`: protoc is installed via choco, ripgrep prefetch supports the msvc triple and matches the `rg.exe` file name, and the packaging step distinguishes `pig.exe` from `pig`.
- Release targets are back to three platforms: linux x64, mac arm64, windows x64.

## Others

- `Cargo.lock`: upgraded `find-msvc-tools` from 0.1.13 to 0.1.14, resolving its incompatibility with `cc` 1.2.48, which was the reason the Windows release had been dropped.
