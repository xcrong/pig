# pig v1.1.0（2026-09-30）

pig 收敛为通用 Agent Harness 后的第一个功能版本：删掉了所有第一方遥测与图像/视频生成工具，解除了 Grok 账号强绑定，新机装完直接走 provider 配置向导；同时带进上游的命令沙箱隔离与出网代理子系统。

## 新功能

- 新机引导：欢迎页在没有凭证时直接给出 Setup provider 入口（`s` 或回车进入），逐个列出内建 vendor 并检测对应 `env_key` 是否已设置，确认或粘贴后写入受信 `config.toml`；也可以分步手填自定义 provider（id、base URL、model、backend、credential），落盘到 `model_providers` 与 `model`。入口不再是一条死路。
- 自定义 provider 向导新增后端选择指导：`base_url` 复用 vendor 归一化规则（messages 网关自动补 `/v1`），并在 messages 网关与 Anthropic 直连之间分支——直连会自动写入 `anthropic-version`（默认 `2023-06-01`）与 `auth_scheme = x_api_key`。确认页会显示实际生效的认证方式、env 是否找到、以及 responses 等高级字段提示。
- Vendor 快照自动更新：构建阶段拉取 pi.dev 最新模型切片直接编进二进制（离线或沙箱环境回落到仓库内 git 快照），运行时后台定时刷新 `~/.config/pig/vendors` 下的缓存。加载优先级为「显式文件 > 自动缓存 > 内建」，未启用的 vendor 永不触发拉取。
- 命令沙箱隔离：移植上游的 sandbox command 子系统与出网代理（egress-proxy），workspace 接管沙箱与门禁判定。沙箱模式支持 `off` / `observe` / `enforce` 三档，分层为「远端 rollout 开关 < 用户 `config.toml` < workspace 层（只收紧不放宽）< `GROK_SANDBOX_MODE`」，且当前层级被拒绝时按 enforce 处理并标记来源。
- MCP 服务器支持 `bearer_token_file`：从文件读取 Bearer token，**每次请求重读**，磁盘上轮转的凭证无需重连即可生效；它会顶掉配置里的 `Authorization` 头。路径支持 setup 模板变量替换。
- 新增 npm 包 `@xcrong/pig`，postinstall 按平台从 GitHub Release 下载预编译二进制，并写入 `installer = npm` 让后续更新交给包管理器。
- 权限路径匹配升级为双匹配，sandbox 相关门禁补洞，剪贴板操作串行化，MCP 服务器去重。
- `/v1/settings` 收来的 leader mode 建议改为保活而非一次性提示，recap 改为省 token 的写法，per-path 并发，建议（suggest）路由重排。

## 修复

- 修复 Setup provider 向导只有键盘能走通的问题：三处列表现在都支持鼠标——hover 高亮即选中、单击选中或确认，框内外点击一律吞掉不穿透到下层 welcome 菜单，小终端下会清空过期 hit-rects 防 panic。
- 修复欢迎页在没有凭证时直接显示红色报错、并把用户反复带回同一个报错的死路。
- 修复 `xai-grok-config` 的单测目标编译不过：`sandbox_mode_tests.rs` 里的远端设置用例从上游移植过来时带着 `crate::remote_settings` 导入，而该结构实际住在 `xai-grok-config-types`（反向依赖，无法回引）。已把该用例迁到 `xai-grok-config-types`，`cargo test -p xai-grok-config` 恢复可跑。
- 修复 bearer token 文件的读取时机（此前只在连接时读一次，轮转后不生效）。
- 清理一批 `cargo build` 存量 warning：只写不读的中间值、不可达的 `pub` 收窄为 `pub(crate)`、无意义的 `drop`。

## 品牌与界面

- 界面产品名统一为 Pig Agent，欢迎页版本徽标、副标题与信任提示不再出现上游 `Grok Build` 字样。
- `pig --version` 的版本横幅改为 `pig` 前缀。

## 破坏性变更

- **删除 Grok OAuth 浏览器登录与开机强制鉴权。** xAI OIDC loopback 回调、device code 流程、开机自动弹浏览器一并移除，`pig login` / `grok login` 命令入口、`--oauth` / `--device-auth`、`GROK_LOGIN_DEVICE_FLOW` 等环境变量不再存在。凭证改为通过 `[vendors.<id>]`（`enabled` + `env_key`）或 `[model_providers.*]` 配置；TUI 直接启动，无凭证时不再弹浏览器。原先依赖 Grok 账号登录的用户需要改走 provider 配置。
- **删除全部第一方遥测。** `xai-grok-telemetry`、`xai-grok-otel`、`xai-mixpanel` 三个 crate 连同全部调用点移除，`[telemetry]` 配置段与相关 `GROK_TELEMETRY_*` 环境变量不再读取。普通日志与本地崩溃报告文件保留。
- **删除图像/视频生成工具**：`/imagine`、`/imagine-video` 与 image_gen / image_edit / image_to_video / reference_to_video 四个工具移除，pig 收敛为通用 Agent Harness。
- **更新器改走 GitHub Release 与包管理器**：`installer` 收敛为 `npm` / `github` / `winget` / 未知，删除了 XAI 下载路径、enterprise 更新通道与 `install.sh`。直接二进制从 `xcrong/pig` 的 Release 纯 HTTPS 发现版本并下载解包。
- 发布产物收缩为 linux x64 与 macOS arm64 两种（ubuntu-arm / mac-intel / windows 暂不发版）。

## 构建与发布

- 新增 `publish-npm` job：tag 推送后自动对齐 `npm/pig` 版本并通过 OIDC 可信发布（无长期 token）。预发布 tag（带 `-N` 后缀）自动进 alpha 通道。
- `[cli].auto_update` 仍默认关闭，pig 不会被上游产物覆盖；更新源本身仍指向上游。
- dev profile 关闭 debuginfo，加快本地迭代。

## 其他

- 上游基线：monorepo `036a5d8`（版本 1.0.41），本次无上游同步；sandbox 隔离与核心变更按 P0/P1 优先级挑选移植。
- 在 `AGENTS.md` 合并保护清单中记入「无第一方遥测出口」的现状，避免后续同步上游时把第一方 sink 带回来。
- 文档新增 TUI 鼠标约定（凡键盘可选中/确认的列表与按钮必须同时支持鼠标）。
